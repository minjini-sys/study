# Amazon EC2 AMI에 호환 인스턴스 타입을 지정할 수 있게 됨

날짜: 2026-09-05  
출처: [AWS What’s New - Amazon EC2 now supports specifying compatible instance types on AMIs](https://aws.amazon.com/about-aws/whats-new/2026/09/ec2-images-supported-instances/)

## 오늘의 AWS 소식

AWS가 2026년 9월 4일에 Amazon EC2 AMI 관련 기능을 업데이트했다.

이제 AMI 소유자는 특정 AMI가 어떤 EC2 인스턴스 타입에서 실행될 수 있는지 직접 지정할 수 있다.

즉, AMI와 맞지 않는 인스턴스 타입으로 실행하려고 하면 AWS가 자동으로 실행을 막아준다.

## 핵심 내용

AMI 소유자는 다음과 같은 설정을 할 수 있다.

- 지원되는 인스턴스 타입 지정
- 지원되지 않는 인스턴스 타입 지정
- 지원/미지원 인스턴스 타입을 둘 다 지정

기존에는 AMI가 기본적으로 모든 인스턴스 타입에서 실행될 수 있었다.

하지만 실제로는 운영체제, 아키텍처, 드라이버, 성능 요구 사항 때문에 특정 인스턴스 타입과 맞지 않는 경우가 생길 수 있다.

이번 기능은 이런 잘못된 조합을 미리 차단해서 실행 실패 위험을 줄여준다.

## 왜 중요한가

EC2를 운영하다 보면 AMI를 여러 팀이나 여러 환경에서 재사용할 수 있다.

이때 누군가가 AMI와 맞지 않는 인스턴스 타입을 선택하면 인스턴스 실행이 실패하거나, 실행되더라도 기대한 방식으로 동작하지 않을 수 있다.

이번 업데이트를 사용하면 AMI 자체에 호환 가능한 인스턴스 타입 정보를 넣을 수 있기 때문에 운영 실수를 줄일 수 있다.

특히 다음 상황에서 유용하다.

- 특정 CPU 아키텍처에서만 동작하는 AMI를 배포할 때
- GPU, Inferentia, Trainium 같은 특수 하드웨어가 필요한 워크로드를 운영할 때
- 조직 안에서 표준 AMI를 공유할 때
- 테스트되지 않은 인스턴스 타입 사용을 막고 싶을 때

## 기존 동작과 달라진 점

기본 동작은 기존과 같다.

AMI에 제한을 명시하지 않으면 기존처럼 모든 인스턴스 타입에서 실행을 시도할 수 있다.

차이는 AMI 소유자가 제한을 설정했을 때 생긴다.

제한이 설정된 AMI는 허용되지 않은 인스턴스 타입에서 실행이 자동으로 차단된다.

## 비용과 리전

이 기능은 모든 AWS 리전에서 사용할 수 있다.

추가 비용은 없다.
