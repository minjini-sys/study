# Amazon WorkSpaces Core Managed Instances, ModifyVolume API 지원

## 공식 출처

- [Amazon WorkSpaces Core Managed Instances now supports ModifyVolume API](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-workspaces-cmi-modifyvolume/)
- 발표일: 2026년 10월 26일

## 핵심 내용

Amazon WorkSpaces Core Managed Instances에서 실행 중인 인스턴스의 EBS 볼륨을 제자리에서 변경할 수 있는 `ModifyVolume` API를 지원한다.

이 API를 사용하면 볼륨을 분리하거나 인스턴스를 다시 시작하지 않고 다음 항목을 변경할 수 있다.

- 볼륨 크기: 최대 16,384 GiB까지 확장
- 볼륨 유형: 지원되는 Amazon EBS 볼륨 유형 간 전환
- IOPS: `gp3`, `io1`, `io2` 볼륨의 IOPS 조정
- 처리량: `gp3` 볼륨의 처리량 조정

이전에는 스토리지 용량이나 성능을 바꾸기 위해 Managed Instance를 다시 구축해야 했다. 이번 업데이트로 운영 중인 데스크톱 인프라의 스토리지를 더 간단하게 확장하거나 성능 요구에 맞게 조정할 수 있다.

## 왜 중요한가

가상 데스크톱 환경은 사용자 데이터 증가, 애플리케이션 설치, 프로필 크기 변화로 인해 필요한 저장 공간과 I/O 성능이 계속 달라질 수 있다. 인스턴스를 재구축하는 방식은 작업 시간이 길고 사용자 중단 위험도 있었다.

제자리 변경을 사용하면 다음과 같은 장점이 있다.

- 재구축 절차와 작업 시간을 줄일 수 있다.
- 볼륨 분리나 인스턴스 재시작 없이 변경할 수 있다.
- 실제 사용량에 따라 용량과 성능을 단계적으로 조정할 수 있다.
- 과도하게 할당된 IOPS나 처리량을 조정해 비용을 최적화할 수 있다.
- 파트너 VDI 또는 DaaS 솔루션의 운영 자동화에 스토리지 변경 기능을 포함할 수 있다.

## 서비스 및 아키텍처 관점

WorkSpaces Core Managed Instances는 파트너의 VDI 및 DaaS 솔루션이 AWS의 관리형 데스크톱 인프라를 사용할 수 있게 한다. 이번 기능은 데스크톱 인스턴스 자체를 교체하는 대신 연결된 EBS 볼륨의 속성을 변경하는 방식이다.

운영 흐름은 다음과 같이 구성할 수 있다.

1. 모니터링 시스템에서 디스크 사용률 또는 I/O 병목을 감지한다.
2. 자동화 도구가 `ModifyVolume` 요청을 보낸다.
3. EC2의 `DescribeVolumesModifications` API로 변경 상태를 확인한다.
4. 변경이 완료되면 운영체제에서 새 용량과 성능이 반영되었는지 검증한다.
5. 용량을 늘린 경우 파티션과 파일 시스템 확장이 필요한지 확인한다.

볼륨 변경은 비동기 작업이므로 API 호출 성공만으로 전체 작업이 끝났다고 판단하면 안 된다. 변경 상태를 지속적으로 확인하고 성공, 실패, 지연을 운영 이벤트로 기록하는 것이 좋다.

또한 볼륨 크기는 확장할 수 있지만 축소 작업으로 생각해서는 안 된다. 축소가 필요하다면 새 볼륨으로 데이터를 옮기는 별도 마이그레이션 절차를 검토해야 한다.

## 보안 관점

- `ModifyVolume` 권한은 스토리지 구성을 변경해야 하는 운영 역할에만 최소 권한으로 부여한다.
- 변경 요청과 결과를 CloudTrail에서 추적할 수 있도록 로깅을 유지한다.
- 자동화 역할이 임의의 볼륨을 변경하지 못하도록 리소스와 조건을 이용해 IAM 정책 범위를 제한한다.
- 중요한 데스크톱 데이터는 EBS 암호화와 적절한 KMS 키 정책으로 보호한다.
- 대규모 변경 전에는 스냅샷과 복구 절차가 준비되어 있는지 확인한다.

## 운영 관점

`ModifyVolume`은 멱등성 토큰을 지원한다. 네트워크 오류나 타임아웃으로 같은 요청을 다시 보내더라도 중복 변경을 방지하도록 자동화 코드에 고유한 토큰을 포함하는 것이 좋다.

운영 시에는 다음 항목을 함께 관리해야 한다.

- 변경 전후의 볼륨 크기, 유형, IOPS, 처리량 기록
- `DescribeVolumesModifications`를 이용한 진행 상태 확인
- 실패 또는 장시간 지연에 대한 알림
- 변경 후 운영체제와 애플리케이션 수준의 용량 확인
- CloudWatch 지표를 이용한 성능 개선 여부 검증
- EBS 유형과 프로비저닝 성능 변경에 따른 비용 확인

특히 `gp3`는 용량과 IOPS, 처리량을 각각 조정할 수 있으므로 워크로드에 필요한 값을 따로 산정해야 한다. 높은 수치를 무조건 설정하기보다 실제 지표를 근거로 조정하는 것이 비용과 성능 측면에서 유리하다.

## 시험 관점 정리

AWS 시험이나 아키텍처 문제에서는 다음 개념을 연결해서 기억할 수 있다.

- EBS 볼륨은 실행 중인 인스턴스에서도 속성을 변경할 수 있다.
- 볼륨 변경은 비동기 작업이므로 상태 확인이 필요하다.
- `gp3`는 용량과 별개로 IOPS와 처리량을 조정할 수 있다.
- 자동화된 API 재시도에는 멱등성이 중요하다.
- IAM 최소 권한, CloudTrail 감사 로그, EBS 암호화는 변경 작업의 보안 기반이다.
- 용량 확장 후 운영체제의 파티션과 파일 시스템 작업이 별도로 필요할 수 있다.

## 같이 보면 좋은 학습 포인트

- Amazon EBS 볼륨 유형별 특징: `gp3`, `io1`, `io2`
- EBS Elastic Volumes와 볼륨 수정 상태
- `ModifyVolume` 및 `DescribeVolumesModifications` API
- EBS 볼륨 확장 후 파일 시스템 확장 방법
- IAM 최소 권한 정책과 CloudTrail 감사
- WorkSpaces Core와 파트너 VDI 아키텍처
- 스토리지 성능 지표와 비용 최적화

## 한 줄 정리

WorkSpaces Core Managed Instances의 `ModifyVolume` 지원으로 인스턴스를 재구축하지 않고도 EBS 용량과 성능을 운영 중에 조정할 수 있게 되었다.
