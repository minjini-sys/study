# Amazon Cognito Plus 플랜, 99.99% SLA 제공

## 공식 출처

- [Amazon Cognito announces 99.99% Service Level Agreement for the Plus feature plan](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cognito-sla-update/)
- 발표일: 2026년 11월 5일
- 적용 시작일: 2026년 11월 1일

## 핵심 내용

Amazon Cognito가 Plus 기능 플랜의 사용자 풀(user pool)에 대해 월간 가동률 99.99%의 Service Level Agreement(SLA)를 제공한다. 기존 Plus 플랜의 서비스 약속은 99.9%였으며 이번 업데이트로 한 단계 높아졌다.

플랜별 SLA는 다음과 같다.

- Plus: 월간 가동률 99.99%
- Essentials: 월간 가동률 99.9%
- Lite: 월간 가동률 99.9%

이미 Plus 플랜을 사용하는 사용자 풀은 새로운 서비스 약속이 자동 적용된다. 다른 플랜의 사용자 풀은 AWS Management Console, AWS CLI 또는 AWS SDK를 통해 Plus로 전환할 수 있다.

Plus 플랜에는 향상된 SLA 외에도 다음과 같은 위협 보호 기능이 포함된다.

- 적응형 인증(adaptive authentication)
- 유출된 자격 증명 탐지(compromised credentials detection)
- 위협 및 사용자 활동 로깅과 내보내기

## 왜 중요한가

Cognito 사용자 풀은 회원 가입, 로그인, 토큰 발급과 계정 복구 같은 애플리케이션의 인증 경로를 담당한다. 인증 서비스가 중단되면 애플리케이션 서버가 정상이어도 신규 로그인이나 토큰 갱신이 실패해 사용자가 서비스를 이용하지 못할 수 있다.

월간 가동률을 단순 시간으로 환산하면 99.9%는 한 달에 약 43분, 99.99%는 약 4분 수준의 비가용 시간에 해당한다. 이는 이해를 위한 근사치이며 실제 SLA 측정 방식, 제외 조건과 보상 기준은 Amazon Cognito SLA 원문을 따라야 한다.

더 높은 서비스 약속은 다음과 같은 워크로드에서 특히 의미가 있다.

- 로그인 중단이 매출 손실로 이어지는 전자상거래
- 업무 시간 전체에 인증이 필요한 기업용 SaaS
- 대규모 소비자 대상 모바일 및 웹 애플리케이션
- 보안 위협 탐지와 사용자 활동 감사가 중요한 서비스

## 서비스 및 아키텍처 관점

Cognito의 SLA가 높아져도 애플리케이션 전체의 가용성이 자동으로 99.99%가 되는 것은 아니다. 인증 흐름에는 Cognito 외에도 DNS, CloudFront, API Gateway, 애플리케이션 서버, 데이터베이스와 외부 IdP가 포함될 수 있으며 각 구성 요소의 장애가 전체 로그인 성공률에 영향을 준다.

일반적인 인증 흐름은 다음과 같다.

1. 사용자가 애플리케이션에서 로그인을 시작한다.
2. Cognito 사용자 풀 또는 연결된 외부 IdP가 사용자를 인증한다.
3. Cognito가 ID, Access, Refresh Token을 발급한다.
4. 애플리케이션이나 API가 토큰의 서명과 클레임을 검증한다.
5. 토큰 만료 시 클라이언트가 갱신 또는 재인증을 수행한다.

고가용성 설계에서는 인증 장애가 모든 기능을 즉시 중단시키지 않도록 이미 발급된 토큰을 표준에 맞게 로컬 검증하고, 토큰 수명과 갱신 전략을 업무 위험에 맞게 구성해야 한다. 단, 만료된 토큰을 임의로 허용하거나 인증 실패를 우회해서는 안 된다.

Plus 플랜 전환 전에는 사용자 수, 월간 활성 사용자, 위협 보호 사용량과 가격을 검토하고, 실제 업무의 복구 시간 목표와 보안 요구사항에 맞는지 판단해야 한다.

## 보안 관점

- 적응형 인증을 이용해 로그인 위험 수준에 따라 추가 인증을 요구할 수 있다.
- 유출된 자격 증명 탐지로 알려진 침해 자격 증명의 사용을 식별하고 대응한다.
- 위협 및 사용자 활동 로그를 중앙 로그 저장소나 SIEM으로 내보내 분석한다.
- MFA, 강력한 암호 정책과 계정 복구 정책을 함께 구성한다.
- 앱 클라이언트별 OAuth 흐름, 콜백 URL과 로그아웃 URL을 최소 범위로 제한한다.
- 사용자 풀과 앱 클라이언트 변경 권한에는 IAM 최소 권한을 적용하고 CloudTrail로 감사한다.
- 토큰을 브라우저나 모바일 앱에 저장할 때 XSS, 탈취와 장기 보관 위험을 고려한다.

99.99% SLA는 가용성에 대한 서비스 약속이며 계정 탈취나 잘못된 권한 설정을 방지하는 보안 보장은 아니다. 위협 보호 기능을 실제로 설정하고 로그를 모니터링해야 보안 효과를 얻을 수 있다.

## 운영 관점

SLA는 장애가 발생하지 않는다는 약속이 아니라 계약에서 정의한 월간 가동률 기준과 조건을 의미한다. 따라서 서비스 상태, 실제 로그인 성공률과 사용자 영향은 별도로 관측해야 한다.

운영 시에는 다음 항목을 관리한다.

- 사용자 풀별 Lite, Essentials, Plus 플랜 상태
- 로그인, 회원 가입, 토큰 갱신의 성공률과 지연 시간
- Cognito API 오류와 제한 초과
- 외부 IdP와 이메일·SMS 전달 서비스의 상태
- 적응형 인증과 유출 자격 증명 탐지 이벤트
- 위협 및 사용자 활동 로그 내보내기 상태
- Plus 플랜 전환 전후의 비용
- SLA 원문의 측정 방식, 제외 조건과 크레딧 요청 절차

CloudWatch 지표와 애플리케이션 수준의 합성 로그인을 함께 사용하면 Cognito API 상태뿐 아니라 사용자가 실제로 인증 흐름을 완료할 수 있는지 확인할 수 있다.

## 시험 관점 정리

AWS 시험이나 아키텍처 문제에서는 다음 개념을 연결해서 기억할 수 있다.

- Cognito 사용자 풀은 애플리케이션 사용자의 가입과 인증을 관리한다.
- Cognito Identity Pool은 인증된 사용자에게 AWS 자격 증명을 제공하는 용도다.
- Plus 사용자 풀의 SLA는 99.99%이고 Essentials와 Lite는 99.9%다.
- SLA는 서비스 약속이며 애플리케이션 전체의 고가용성을 자동 보장하지 않는다.
- 적응형 인증은 위험 기반으로 추가 인증을 적용하는 기능이다.
- 유출된 자격 증명 탐지는 계정 탈취 방어에 도움을 준다.
- ID Token, Access Token, Refresh Token은 목적과 수명이 서로 다르다.
- 인증 경로의 모든 의존성을 모니터링해야 실제 사용자 가용성을 판단할 수 있다.

Amazon Cognito Plus 사용자 풀은 99.99% SLA와 위협 보호 기능을 제공해 높은 인증 가용성과 계정 보안이 필요한 애플리케이션에 더 강한 운영 기준을 제공한다.
