# AWS Network Firewall, 차세대 방화벽 정책 출시

## 공식 출처

- [AWS Network Firewall launches next-generation firewall policy](https://aws.amazon.com/about-aws/whats-new/2026/11/network-firewall-launches-ngfw-policy/)
- 발표일: 2026년 11월 10일

## 핵심 내용

AWS Network Firewall에 차세대 방화벽(Next-Generation Firewall, NGFW) 정책 모델이 추가됐다. 새 정책은 방화벽 접근 제어와 침입 방지 시스템(IPS) 보호를 하나의 용량 안에서 경쟁시키지 않고 서로 다른 계층과 용량으로 관리한다.

주요 변화는 다음과 같다.

- 방화벽 규칙으로 기본 거부(deny-by-default) 접근 제어를 구성할 수 있다.
- 승인된 도메인만 허용하는 방식으로 아웃바운드 통신 범위를 제한할 수 있다.
- IPS에는 AWS 또는 AWS Marketplace 파트너의 관리형 규칙 그룹을 사용할 수 있다.
- 자체 사용자 지정 IPS 규칙 그룹도 만들 수 있다.
- 방화벽 규칙과 IPS 규칙이 각각 독립적인 용량을 사용한다.
- 여러 정책에서 공유하지 않는 규칙은 사전 용량 할당 없이 내장 규칙 그룹으로 구성할 수 있다.
- 모든 규칙은 상태 저장 방식이며 전체 연결 컨텍스트를 기준으로 평가된다.
- 기존 정책은 변경 없이 계속 작동하고 IPS 규칙도 하위 호환된다.
- 모든 상용 AWS 리전과 AWS GovCloud(US) 리전에서 추가 기능 요금 없이 제공된다.

## 왜 중요한가

기존 정책에서 접근 제어와 위협 탐지 규칙을 함께 관리하면 규칙 구조와 용량 계획이 복잡해질 수 있다. 한 종류의 규칙을 늘리기 위해 다른 종류의 규칙 용량을 줄여야 하는 상황도 운영 부담을 키운다.

NGFW 정책은 허용할 통신을 결정하는 방화벽 계층과 알려진 공격 패턴을 탐지·차단하는 IPS 계층을 분리한다. 보안팀은 먼저 기본 거부 원칙으로 통신 범위를 좁히고, 그 위에 지속적으로 업데이트되는 위협 방어 규칙을 적용할 수 있다. 정책의 목적과 책임이 명확해져 변경 검토, 감사와 장애 분석도 쉬워진다.

## 서비스 및 아키텍처 관점

AWS Network Firewall은 VPC 트래픽 경로에 배치하는 관리형 네트워크 보안 서비스다. NGFW 정책을 적용하더라도 검사 대상 트래픽이 실제 방화벽 엔드포인트를 지나도록 라우팅해야 한다.

일반적인 처리 흐름은 다음과 같이 이해할 수 있다.

1. VPC 라우팅으로 검사할 트래픽을 Network Firewall 엔드포인트에 전달한다.
2. 방화벽 규칙이 기본 거부 원칙에 따라 허용된 목적지와 통신인지 판단한다.
3. 허용된 연결에도 IPS 규칙을 적용해 알려진 위협과 공격 패턴을 검사한다.
4. 상태 저장 규칙이 전체 연결 컨텍스트를 바탕으로 일관되게 트래픽을 처리한다.
5. 방화벽 로그와 경보를 보안 모니터링 및 대응 절차에 연결한다.

중앙 보안 VPC 또는 AWS Transit Gateway와 결합할 때는 대칭 라우팅을 유지하고 각 가용 영역의 방화벽 엔드포인트를 사용하도록 경로를 설계해야 한다. 이는 이번 발표의 새 기능이라기보다 Network Firewall 아키텍처를 적용할 때 함께 점검해야 하는 기본 원칙이다.

## 보안 관점

- 기본 거부 정책으로 필요한 도메인과 목적지만 명시적으로 허용한다.
- AWS 관리형 규칙 그룹은 새로운 위협에 맞춰 자동 업데이트되는 장점이 있다.
- Marketplace 규칙을 선택할 때 공급자, 탐지 범위, 업데이트 정책과 비용을 검토한다.
- 조직 고유의 위협 모델은 사용자 지정 IPS 규칙으로 보완한다.
- 정책 변경 권한에는 IAM 최소 권한을 적용하고 CloudTrail로 변경 이력을 감사한다.
- 경고와 차단 로그를 중앙 로그 계정 또는 SIEM으로 전달한다.
- 규칙 배포 전 테스트 환경에서 오탐과 정상 트래픽 영향을 확인한다.
- 방화벽은 보안 그룹, 네트워크 ACL, IAM과 애플리케이션 보안을 대체하지 않는다.

NGFW 정책의 계층 분리는 심층 방어를 구성하기 쉽게 만들지만, 잘못된 라우팅으로 검사 경로를 우회하거나 지나치게 넓은 허용 규칙을 만들면 기대한 보호를 얻을 수 없다.

## 운영 관점

기존 정책은 그대로 동작하므로 즉시 마이그레이션할 필요는 없다. 새 정책을 도입할 때는 현재 규칙의 목적과 의존성을 분류한 뒤 접근 제어 규칙과 IPS 규칙으로 나누어 검증하는 방식이 안전하다.

운영 시에는 다음 항목을 확인한다.

- 방화벽 규칙과 IPS 규칙의 독립적인 용량 사용량
- 내장 규칙 그룹과 공유 규칙 그룹의 사용 기준
- 관리형 규칙 그룹의 버전 및 업데이트 영향
- 허용·차단 트래픽과 IPS 경보 추세
- 규칙 변경 후 오탐, 누락과 애플리케이션 장애 여부
- 방화벽 엔드포인트 상태와 가용 영역별 라우팅
- 로그 전달 실패 및 보관 정책
- 기존 정책에서 NGFW 정책으로 전환하기 전후의 동작 비교

NGFW 정책 자체에는 추가 요금이 없지만 AWS Network Firewall 사용량, 로그 저장·분석과 Marketplace 관리형 규칙에는 별도 비용이 발생할 수 있으므로 실제 비용 구조를 확인해야 한다.

## 시험 관점 정리

AWS 시험이나 아키텍처 문제에서는 다음 개념을 연결해서 기억할 수 있다.

- AWS Network Firewall은 VPC를 위한 관리형 네트워크 방화벽 및 위협 탐지 서비스다.
- NGFW 정책은 방화벽 접근 제어와 IPS 보호를 별도 계층으로 구성한다.
- 방화벽 규칙과 IPS 규칙은 각각 독립적인 용량을 가진다.
- 모든 NGFW 정책 규칙은 상태 저장 방식으로 전체 연결 컨텍스트를 평가한다.
- 기본 거부 후 필요한 대상만 허용하는 방식이 최소 권한 네트워크 접근에 부합한다.
- AWS 관리형 또는 Marketplace 관리형 IPS 규칙과 사용자 지정 IPS 규칙을 사용할 수 있다.
- 기존 정책은 변경 없이 계속 운영되며 IPS 규칙은 하위 호환된다.
- 실제 검사를 위해서는 트래픽이 방화벽 엔드포인트를 통과하도록 라우팅해야 한다.

## 같이 보면 좋은 학습 포인트

- 상태 저장 방화벽과 상태 비저장 방화벽의 차이
- IDS와 IPS의 차이
- 기본 거부와 허용 목록 방식
- AWS Network Firewall과 보안 그룹 및 네트워크 ACL 비교
- Transit Gateway를 이용한 중앙 집중식 검사 아키텍처
- 대칭 라우팅과 가용 영역별 방화벽 엔드포인트
- 방화벽 로그를 이용한 탐지 및 사고 대응
- AWS Firewall Manager를 이용한 다중 계정 정책 관리

## 한 줄 정리

AWS Network Firewall의 NGFW 정책은 기본 거부 접근 제어와 IPS 위협 방어를 독립된 계층과 용량으로 제공해 VPC 보안 정책을 더 명확하고 확장 가능하게 운영하도록 돕는다.
