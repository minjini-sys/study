# AWS Backup 논리적 에어갭 볼트, Amazon RDS 지원

## 공식 출처

- [AWS Backup adds logically air-gapped vault support for Amazon RDS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-backup-air-gapped-vault-rds/)

## 핵심 내용

AWS Backup의 논리적 에어갭 볼트(logically air-gapped vault)가 Amazon RDS DB 인스턴스 백업을 지원한다. 이 볼트는 백업을 불변 상태로 격리하고, 다른 AWS 계정과 안전하게 공유해 복구 및 복원 테스트에 사용할 수 있다.

주요 특징은 다음과 같다.

- RDS 스냅샷을 AWS Backup 서비스 소유 계정에 격리해 보관한다.
- AWS Backup Vault Lock의 규정 준수 모드가 기본 적용돼 보존 기간 전 변경이나 삭제를 막는다.
- AWS 소유 키 또는 고객 관리형 AWS KMS 키로 암호화할 수 있다.
- AWS Resource Access Manager(AWS RAM)로 다른 계정에 볼트를 공유할 수 있다.
- 공유받은 계정은 백업을 먼저 복사하지 않고 직접 복원할 수 있다.
- 다자간 승인(Multi-party approval)을 사용해 원래 계정이나 조직이 침해된 상황에서도 독립적인 복구 경로를 구성할 수 있다.
- AWS Backup 복원 테스트와 연결해 실제 복구 가능성을 정기적으로 검증할 수 있다.

이 기능은 논리적 에어갭 볼트와 Amazon RDS를 모두 지원하는 대부분의 AWS 리전에서 제공된다.

## 왜 중요한가

백업 사본이 여러 개 있어도 운영 환경과 같은 보안 경계에 있으면 랜섬웨어, 내부자 위협 또는 계정 침해 시 함께 삭제되거나 암호화될 수 있다. 또한 백업이 존재한다는 사실만으로 실제 복구가 성공한다는 보장은 없다.

논리적 에어갭 볼트는 백업의 불변성과 격리를 제공하고, 별도 복구 계정에서 직접 복원할 수 있게 한다. 복원 테스트까지 결합하면 백업 보유 여부가 아니라 실제 복구 준비 상태를 확인할 수 있다. 특히 규제 대상 데이터와 업무 핵심 RDS 데이터베이스의 사이버 복원력을 높이는 데 의미가 있다.

## 서비스 및 아키텍처 관점

RDS를 위한 일반적인 다중 사본 전략은 다음과 같이 구성할 수 있다.

1. 워크로드 계정의 표준 백업 볼트에 연속 백업을 저장해 PITR과 일상적인 장애 복구에 사용한다.
2. 같은 리전의 논리적 에어갭 볼트에 정기 스냅샷을 보관해 계정 침해와 랜섬웨어에 대비한다.
3. 별도 리전의 표준 볼트에도 복사해 리전 전체 장애에 대비한다.
4. 논리적 에어갭 볼트를 복구 계정과 포렌식 계정에 AWS RAM으로 공유한다.
5. 포렌식 계정에서 정기 복원 테스트와 데이터 검증을 수행한다.
6. 심각한 침해 시 별도 복구 조직의 승인팀이 다자간 승인으로 접근을 허가한다.

RDS의 지속적 백업을 복사하면 PITR 기능이 유지되지 않고 스냅샷이 된다. 따라서 초 단위 시점 복구가 필요하면 표준 볼트의 연속 백업과 에어갭 볼트의 불변 스냅샷을 함께 운영해야 한다. 에어갭 볼트의 RPO는 스냅샷 생성 주기에 따라 달라진다.

## 보안 관점

- Vault Lock 규정 준수 모드로 보존 기간 중 백업 변경과 삭제를 방지한다.
- 운영 계정과 분리된 복구 계정 및 포렌식 계정을 사용한다.
- AWS RAM 공유 권한과 복원 역할에는 최소 권한을 적용한다.
- 다자간 승인팀과 복구 계정을 운영 조직과 별도 AWS Organization에 두는 방안을 검토한다.
- 고객 관리형 KMS 키 정책에 AWS Backup, 복구 계정과 필요한 역할만 허용한다.
- CloudTrail, AWS Backup Audit Manager와 Security Hub로 백업 및 복구 활동을 감사한다.
- 복원한 데이터베이스는 격리된 VPC와 서브넷에서 검사해 운영 네트워크와 분리한다.
- 복구 자격 증명과 승인 절차가 운영 계정 침해에 함께 영향을 받지 않도록 독립성을 유지한다.

소스 RDS가 AWS 관리형 키 `aws/rds`로 암호화된 경우 에어갭 볼트 복사가 지원되지 않는다. 고객 관리형 키로 암호화된 인스턴스 또는 암호화되지 않은 인스턴스를 사용해야 하며, 기존 DB의 키 변경은 스냅샷 복사 및 복원이나 Blue/Green 배포 같은 별도 절차가 필요하다.

## 운영 관점

운영 시에는 다음 항목을 관리한다.

- RDS별 RPO, RTO와 백업 보존 기간
- 표준 볼트와 에어갭 볼트의 백업 작업 및 복사 성공률
- 임시 스냅샷이 에어갭 볼트로 복사되지 않은 실패 상황
- KMS 키 종류와 키 정책의 복구 계정 접근 가능 여부
- AWS RAM 공유 상태와 다자간 승인 담당자
- 정기 복원 테스트 성공률과 실제 복원 시간
- 복원 후 행 수, 스키마 일관성 및 애플리케이션 쿼리 검증
- 백업 저장 비용, 복원 비용과 데이터베이스 크기
- 리전 장애용 교차 리전 사본의 최신성

EventBridge와 Lambda를 이용하면 복원 작업 완료 후 자동으로 데이터 무결성을 검사하고 `PutRestoreValidationResult`로 결과를 기록할 수 있다. 성공적인 복원뿐 아니라 애플리케이션 관점의 데이터 검증까지 통과해야 복구 준비가 됐다고 판단하는 것이 좋다.

## 시험 관점 정리

AWS 시험이나 아키텍처 문제에서는 다음 개념을 연결해서 기억할 수 있다.

- AWS Backup은 여러 AWS 서비스의 백업 정책과 복구 지점을 중앙 관리한다.
- 논리적 에어갭 볼트는 AWS Backup 서비스 소유 계정에 격리된 불변 백업을 저장한다.
- Vault Lock 규정 준수 모드는 보존 기간 전 백업 삭제나 변경을 막는다.
- AWS RAM 공유를 통해 다른 계정에서 직접 복원할 수 있다.
- 다자간 승인은 계정 또는 조직 침해 시 독립적인 백업 접근 경로를 제공한다.
- 복원 테스트는 백업이 실제로 복원되고 검증되는지 정기적으로 확인한다.
- 표준 볼트의 연속 백업은 PITR에, 에어갭 볼트의 스냅샷은 사이버 복구에 적합하다.
- 교차 리전 사본은 리전 전체 장애에 대비하는 별도의 보호 계층이다.

## 한 줄 정리

AWS Backup의 RDS용 논리적 에어갭 볼트는 불변·격리 백업, 교차 계정 직접 복원과 다자간 승인을 결합해 운영 계정이 침해된 상황에서도 데이터베이스를 복구할 수 있는 독립 경로를 제공한다.
