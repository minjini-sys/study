# AWS IAM Access Troubleshooter, AccessDenied 원인 분석 지원

## 공식 출처

- [AWS IAM announces Access Troubleshooter to debug access denied errors](https://aws.amazon.com/about-aws/whats-new/2026/11/iam-access-troubleshooter/)
- 발표일: 2026년 11월 17일

## 핵심 내용

AWS Identity and Access Management(IAM)이 접근 거부 오류의 전체 권한 평가 컨텍스트를 확인할 수 있는 Access Troubleshooter를 출시했다. 지원되는 AWS 서비스와 API의 AccessDenied 오류 메시지에 고유 식별자가 포함되며, 이를 사용해 해당 요청의 권한 평가 상세 정보를 조회할 수 있다.

확인할 수 있는 정보는 다음과 같다.

- 요청을 평가할 때 사용된 권한 부여 컨텍스트
- 평가 대상이 된 정책
- 각 정책 평가 결과
- 접근 거부의 근본 원인을 찾는 데 필요한 관련 정보

기존에는 오류 메시지에 나타난 거부 정책의 ARN을 중심으로 문제를 조사해야 했고, 동일한 요청에 영향을 준 다른 정책과 평가 컨텍스트를 파악하기 어려웠다. Access Troubleshooter는 실제 권한 평가 결과를 바탕으로 문제를 분석하게 해 반복적인 정책 수정과 재시도를 줄인다.

현재 이 기능은 AWS 문서에 명시된 지원 서비스와 API의 접근 거부 오류에 적용된다. 모든 AWS 서비스와 모든 권한 오류가 동일한 상세 정보를 제공한다고 가정하면 안 된다.

## 왜 중요한가

AWS 권한 결정에는 자격 증명 기반 정책뿐 아니라 리소스 기반 정책, 권한 경계, AWS Organizations 서비스 제어 정책(SCP), 세션 정책과 명시적 거부 등이 함께 영향을 줄 수 있다. 따라서 단순히 IAM 역할에 Allow 문을 추가해도 다른 정책의 Deny 때문에 문제가 해결되지 않을 수 있다.

원인을 모른 채 권한을 넓히는 방식은 문제 해결 시간을 늘리고 과도한 권한을 남긴다. Access Troubleshooter는 어떤 정책이 어떻게 평가됐는지 보여주므로 필요한 부분만 수정하고 최소 권한을 유지하는 데 도움을 준다. 개발팀과 보안팀 사이에서 오류 재현 정보와 정책 근거를 공유하기도 쉬워진다.

## 서비스 및 아키텍처 관점

일반적인 문제 해결 흐름은 다음과 같다.

1. 애플리케이션, CLI 또는 콘솔 요청에서 AccessDenied 오류가 발생한다.
2. 지원되는 서비스의 오류 메시지에서 Access Troubleshooter 고유 식별자를 확인한다.
3. 식별자를 사용해 해당 요청의 권한 부여 상세 정보를 조회한다.
4. 평가된 정책, 요청 컨텍스트와 평가 결과를 검토한다.
5. 누락된 Allow, 명시적 Deny 또는 조건 불일치 같은 원인을 식별한다.
6. 필요한 최소 범위의 정책만 수정한다.
7. 동일한 주체, 작업, 리소스와 조건으로 요청을 다시 검증한다.

이 기능은 실제 거부 요청의 평가 정보를 보여주는 진단 도구다. IAM Access Analyzer의 정책 검증, 외부 접근 분석 및 미사용 권한 분석과 목적이 다르며 서로 보완적으로 사용할 수 있다.

## 보안 관점

- 오류를 해결하기 위해 임시로 `Action: *` 또는 `Resource: *`를 허용하지 않는다.
- Access Troubleshooter 결과를 근거로 필요한 작업과 리소스만 추가한다.
- 명시적 Deny가 발견되면 우회하기보다 해당 통제의 보안 목적을 먼저 확인한다.
- SCP, 권한 경계와 리소스 정책은 중앙 보안팀의 승인 절차에 따라 변경한다.
- 권한 평가 상세 정보 자체가 정책 구조와 리소스 정보를 포함할 수 있으므로 조회 권한을 제한한다.
- CloudTrail 이벤트와 애플리케이션 로그를 함께 확인해 요청 주체와 실제 API 호출을 검증한다.
- 조건 키의 리전, 태그, 네트워크 경로, MFA 및 세션 속성이 예상값과 일치하는지 확인한다.
- 수정 후 IAM Access Analyzer 정책 검증과 테스트 환경 재현을 수행한다.

Access Troubleshooter는 권한 문제의 가시성을 높이지만 정책을 자동으로 안전하게 수정해 주는 기능으로 이해하면 안 된다. 최종 변경은 조직의 최소 권한 원칙과 변경 관리 절차를 따라야 한다.

## 운영 관점

운영 시에는 다음 항목을 관리한다.

- AccessDenied 발생 서비스, API 작업과 호출 주체
- 고유 식별자와 장애 티켓 또는 로그의 연결
- 평가된 정책 종류와 실제 거부 원인
- 반복적으로 발생하는 조건 불일치와 정책 누락
- 해결까지 걸린 시간과 재발률
- 임시 권한의 생성, 만료와 제거 여부
- 정책 변경 전후 CloudTrail 이벤트
- Access Troubleshooter 지원 서비스와 API 범위의 변화

오류 티켓에는 민감한 자격 증명 대신 요청 시간, 주체 ARN, 작업, 대상 리소스, 리전, 요청 ID와 Troubleshooter 식별자를 남기는 것이 좋다. 반복되는 오류는 역할 설계, 태그 정책 또는 배포 파이프라인에 구조적인 문제가 있는지 검토해야 한다.

## 시험 관점 정리

AWS 시험이나 아키텍처 문제에서는 다음 개념을 연결해서 기억할 수 있다.

- IAM의 기본 동작은 명시적으로 허용되지 않은 요청을 거부하는 것이다.
- 명시적 Deny는 일반적인 Allow보다 우선한다.
- 권한 결정에는 자격 증명 정책, 리소스 정책, 권한 경계, SCP와 세션 정책 등이 영향을 줄 수 있다.
- IAM Access Troubleshooter는 지원되는 AccessDenied 오류의 권한 평가 컨텍스트와 정책 평가 결과를 보여준다.
- 오류 메시지의 고유 식별자를 사용해 해당 권한 평가 정보를 조회한다.
- 문제 해결은 전체 권한을 넓히는 것이 아니라 거부 원인을 찾아 최소 범위로 수정해야 한다.
- CloudTrail은 실제 API 호출과 호출 주체를 감사하는 데 사용한다.
- IAM Access Analyzer는 정책 검증과 접근 분석에 사용하며 Access Troubleshooter와 역할이 다르다.

## 같이 보면 좋은 학습 포인트

- IAM 정책 평가 논리
- 명시적 Deny와 암시적 Deny
- AWS Organizations SCP
- IAM Permissions Boundary
- 리소스 기반 정책과 자격 증명 기반 정책
- IAM 조건 키와 ABAC
- CloudTrail을 이용한 API 감사
- IAM Access Analyzer 정책 검증

## 한 줄 정리

AWS IAM Access Troubleshooter는 AccessDenied 오류에 사용된 정책과 권한 평가 컨텍스트를 보여줘 과도한 권한 부여 없이 거부 원인을 빠르게 찾아 수정하도록 돕는다.
