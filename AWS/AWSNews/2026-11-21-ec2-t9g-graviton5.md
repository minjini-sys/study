# Graviton5 기반 Amazon EC2 T9g 인스턴스 정식 출시

- 정리 날짜: 2026-11-21
- 공식 발표일: 2026-11-20
- 공식 출처: [Introducing Amazon EC2 T9g instances based on Graviton5](https://aws.amazon.com/about-aws/whats-new/2026/11/ec2-t9g-instances-ga/)

## 핵심 내용

AWS가 Graviton5 프로세서를 탑재한 저비용 버스터블 범용 인스턴스 `T9g`를 정식 출시했다. T9g는 평소 CPU 사용률은 낮거나 보통이지만 일시적으로 더 높은 CPU 성능이 필요한 워크로드를 대상으로 한다.

AWS가 발표한 T4g 대비 주요 개선 사항은 다음과 같다.

- 최대 45% 향상된 가격 대비 성능
- 최대 2.3배의 컴퓨팅 성능
- 최대 1.5배의 네트워크 대역폭
- 최대 2.8배의 EBS 대역폭
- 6세대 AWS Nitro 카드와 Nitro Isolation Engine 적용

크기는 `nano`, `micro`, `small`, `medium` 네 가지이며, T4g와 동일하게 CPU 크레딧 기반의 Standard 모드와 Unlimited 모드를 지원한다. `T9g.micro`와 `T9g.small`은 AWS Free Tier 대상이다.

구매 방식은 On-Demand, Spot Instances, Savings Plans를 지원한다. 출시 시점에는 미국 동부(버지니아 북부, 오하이오), 미국 서부(캘리포니아 북부, 오리건), 캐나다 중부, 상파울루, 프랑크푸르트, 스페인, 말레이시아, 싱가포르, 시드니, 도쿄 리전에서 사용할 수 있다.

## 왜 중요한가

T 계열은 지속적으로 높은 CPU가 필요하지 않은 서버가 유휴 시간에 CPU 크레딧을 쌓고, 짧은 부하 급증 시 이를 사용하도록 설계된 인스턴스다. 따라서 개발·테스트 환경, 저트래픽 웹 서비스, 소규모 데이터베이스, 마이크로서비스, 로그인 게이트웨이, 짧은 배치 및 CI/CD 작업처럼 평균 CPU 사용률이 낮은 환경의 비용을 줄이는 데 적합하다.

T9g는 T4g의 운영 모델을 유지하면서 컴퓨팅·네트워크·스토리지 성능을 높였다. 기존 T4g 워크로드는 CPU 크레딧 정책을 크게 바꾸지 않고도 성능과 총소유비용(TCO)을 개선할 후보가 생겼다.

다만 AWS가 밝힌 성능 수치는 최대값이며, 실제 이점은 애플리케이션 특성, 인스턴스 크기, CPU 크레딧 소비, EBS 구성과 네트워크 패턴에 따라 달라진다. 운영 환경에서는 자체 벤치마크가 필요하다.

## 서비스·아키텍처 관점

T9g는 Arm64 아키텍처인 AWS Graviton5를 사용한다. x86 기반 인스턴스에서 이전할 때는 운영체제 이미지, 컨테이너 이미지, 언어 런타임, 네이티브 라이브러리와 상용 에이전트가 Arm64를 지원하는지 먼저 확인해야 한다.

아키텍처를 설계할 때는 다음 사항을 고려할 수 있다.

- 지속적인 고부하보다 간헐적인 부하 급증이 있는 서비스에 배치한다.
- Auto Scaling 그룹에서 T9g 기반 시작 템플릿을 시험하고 부하 테스트 후 점진적으로 전환한다.
- 멀티 아키텍처 컨테이너 이미지를 사용하면 x86과 Graviton 인스턴스를 함께 운영하기 쉽다.
- 네트워크나 EBS가 병목인 기존 T4g 워크로드는 향상된 대역폭의 실제 효과를 측정한다.
- CPU를 계속 많이 사용하는 서비스는 T 계열보다 M, C 등 고정 성능 계열과 비용을 비교한다.

## 보안 관점

T9g는 6세대 AWS Nitro System을 기반으로 하며, Nitro Isolation Engine은 형식 검증을 활용해 고객 워크로드 간 및 AWS 운영자와 고객 워크로드 간 격리에 대한 수학적 보증을 제공하도록 설계됐다.

하지만 인스턴스 격리가 애플리케이션 보안을 대신하지는 않는다. IAM 역할 최소 권한, 보안 그룹 제한, IMDSv2 적용, EBS 암호화, Systems Manager를 통한 패치와 접근 관리, 취약점 점검은 계속 필요하다. Arm64로 이전할 때 사용하는 새 AMI와 컨테이너 이미지도 기존 보안 기준을 동일하게 충족해야 한다.

## 운영 관점

- `CPUCreditBalance`와 `CPUSurplusCreditBalance` 같은 CloudWatch 지표로 크레딧 상태를 관찰한다.
- Standard 모드는 크레딧을 소진하면 기준 성능으로 제한될 수 있고, Unlimited 모드는 장시간 기준 성능을 초과하면 추가 비용이 발생할 수 있음을 고려한다.
- T4g와 T9g를 동일한 요청 패턴으로 비교해 처리량, 지연 시간, EBS·네트워크 성능과 비용을 측정한다.
- 프로덕션 전환 전 Arm64 패키지, 관측 에이전트, 백업 도구 및 보안 도구의 호환성을 검증한다.
- 현재 제공 리전을 확인하고, 다중 리전 설계에서는 모든 대상 리전에 T9g가 있는지 확인한다.
- Spot을 사용할 때는 중단 처리를 구현하고, 안정적인 기본 용량은 On-Demand 또는 Savings Plans와 조합한다.

## 시험 관점 정리

AWS 자격시험에서는 다음 연결 관계를 기억하면 좋다.

- **T 계열**: CPU 크레딧을 사용하는 버스터블 범용 인스턴스
- **Standard 모드**: 획득한 크레딧 범위에서 버스트하고, 소진 시 기준 성능으로 동작
- **Unlimited 모드**: 필요하면 기준 성능을 장시간 초과할 수 있지만 추가 크레딧 비용이 발생할 수 있음
- **Graviton**: AWS가 설계한 Arm 기반 프로세서로 가격 대비 성능 최적화에 활용
- **Nitro System**: 가상화, 스토리지, 네트워킹 및 보안 기능을 전용 하드웨어와 경량 하이퍼바이저로 분리
- **Savings Plans**: 일정 사용량을 약정해 컴퓨팅 비용을 절감하는 구매 옵션

문제에서 평균 CPU 사용률은 낮지만 간헐적으로 급증하는 소규모 Arm 호환 워크로드의 비용 효율을 묻는다면 T9g가 후보가 될 수 있다. 반대로 CPU가 지속적으로 높은 워크로드라면 버스터블 계열보다 다른 인스턴스 패밀리를 검토해야 한다.

3. x86에서 Arm64로 마이그레이션할 때의 호환성 점검 항목
4. Graviton과 AWS Nitro System의 역할 차이
5. On-Demand, Spot, Savings Plans의 사용 사례 비교

## 한 줄 정리

Amazon EC2 T9g는 Graviton5와 6세대 Nitro를 기반으로 T4g보다 높은 가격 대비 성능과 대역폭을 제공하는 버스터블 인스턴스로, 간헐적 CPU 부하를 가진 Arm64 호환 워크로드의 비용 최적화에 적합하다.
