# Amazon Textract Insights 정식 출시

- 정리 날짜: 2026-11-23
- 공식 발표일: 2026-11-20
- 공식 발표: [Amazon Textract Insights is now generally available](https://aws.amazon.com/about-aws/whats-new/2026/11/textract-insights-ga/)
- 공식 기술 블로그: [Announcing Amazon Textract Insights: Verifiable generative AI for documents](https://aws.amazon.com/blogs/machine-learning/announcing-amazon-textract-insights-verifiable-generative-ai-for-documents/)

## 핵심 내용

AWS가 생성형 AI 기반 문서 이해 기능인 Amazon Textract Insights를 정식 출시했다. 하나의 비동기 요청으로 여러 문서가 섞인 파일을 논리적인 하위 문서로 분리하고, 각 문서의 유형을 분류한 다음 필요한 필드를 구조화된 데이터로 추출할 수 있다.

사용자는 추출할 필드를 자연어 설명과 함께 JSON Schema 형식의 `blueprint`로 정의한다. W-2, 송장, 은행 명세서처럼 AWS가 제공하는 공개 블루프린트로 시작하거나 업무 문서에 맞는 사용자 정의 블루프린트를 만들 수 있다. 여러 블루프린트를 프로젝트에 등록하면 Textract Insights가 각 하위 문서에 가장 적합한 블루프린트를 연결한다.

각 추출 값에는 신뢰도 점수와 원본 페이지의 위치 정보가 포함된다. 따라서 높은 신뢰도의 결과는 자동 처리하고 낮은 신뢰도의 결과는 사람이 검토하도록 분기할 수 있다. 문서 요약, 그림 설명, 개인 식별 정보(PII) 탐지·마스킹을 지원하며, RAG 애플리케이션에 활용할 수 있도록 Markdown, HTML 및 일반 텍스트도 반환할 수 있다.

입력 문서는 고객의 Amazon S3 버킷에서 읽고 결과도 고객 S3 버킷에 기록한다. AWS SDK와 AWS CLI에서 사용할 수 있으며, 출시 시점에는 미국 동부(버지니아 북부)와 미국 서부(오리건) 리전에서 제공된다.

## 왜 중요한가

보험 청구서, 대출 서류, 세금 자료, 입사 서류처럼 실제 업무에서 들어오는 파일은 서로 다른 문서가 순서 없이 하나의 PDF나 스캔으로 합쳐진 경우가 많다. 기존에는 OCR, 문서 분할, 분류 모델, 필드 추출, 검토 화면을 각각 조합하고 운영해야 했다.

Textract Insights는 이 흐름을 관리형 API 하나로 통합한다. 별도 AI 모델을 학습하지 않고도 필요한 정보를 자연어로 설명할 수 있어 초기 구축 부담을 줄이고, 신뢰도와 원본 위치를 함께 제공해 생성형 AI 결과를 검증하기 쉽게 만든다.

특히 금융·보험·의료·공공 분야처럼 결과의 근거와 감사 가능성이 중요한 업무에서는 단순히 자연스러운 답변을 생성하는 것보다 어떤 페이지와 영역에서 값이 추출됐는지 확인할 수 있는지가 중요하다. 이 기능은 자동화 비율을 높이면서 사람 검토 지점을 명확히 정하는 데 도움이 된다.

## 서비스·아키텍처 관점

대표적인 처리 흐름은 다음과 같다.

1. 원본 PDF 또는 이미지 파일을 입력 S3 버킷에 저장한다.
2. 추출 필드를 설명한 블루프린트와 프로젝트를 생성한다.
3. 애플리케이션이 `StartDocumentInsights` 비동기 작업을 요청한다.
4. Textract Insights가 문서 패킷을 분할하고 유형을 분류한다.
5. 블루프린트에 따라 필드를 추출하고 신뢰도와 페이지 위치를 생성한다.
6. 결과를 출력 S3 버킷에 저장한다.
7. Step Functions, Lambda 또는 이벤트 기반 처리 계층이 결과를 후속 시스템으로 전달하거나 사람 검토 대기열로 보낸다.

공식 기술 블로그에 따르면 단일 파일은 최대 3,000페이지까지 처리할 수 있다. PDF, PNG, JPEG, TIFF 입력을 지원하며 영어, 프랑스어, 독일어, 이탈리아어, 포르투갈어, 스페인어 문서를 처리한다. 실제 설계에서는 문서 크기와 페이지 수, 처리 시간, 지원 언어 및 리전 제약을 먼저 확인해야 한다.

RAG에 연결할 때는 Textract Insights가 반환한 Markdown·HTML·텍스트를 청크로 나누어 검색 인덱스나 벡터 저장소에 적재할 수 있다. 구조화 필드는 업무 시스템에 전달하고, 원문 기반 텍스트는 검색과 질의응답에 사용하는 이중 경로도 구성할 수 있다.

## 보안 관점

Textract Insights는 사용자가 지정한 S3 버킷에서 문서를 읽고 결과를 쓴다. 실행 역할에는 필요한 버킷과 객체에 대한 최소한의 `s3:GetObject` 및 `s3:PutObject` 권한만 부여하고, 버킷 정책으로 예상하지 않은 계정과 네트워크 경로의 접근을 제한해야 한다.

프로젝트와 블루프린트는 기본적으로 AWS 소유 키로 저장 시 암호화된다. `CreateProject` 또는 `CreateBlueprint`의 암호화 설정에서 고객 관리형 AWS KMS 키를 지정할 수 있다. 분석 작업의 중간 데이터도 암호화되며, 고객 관리형 키를 지정하면 해당 키로 보호되고 작업 완료 후 임시 데이터는 삭제된다. 출력 결과에는 대상 S3 버킷의 기본 암호화 설정이 적용된다.

Textract Insights는 가용 컴퓨팅을 위해 요청이 시작된 지리적 영역 안에서 교차 리전 추론을 사용할 수 있다. 데이터 레지던시 요구 사항이 있는 조직은 요청 리전과 실제 처리 가능한 대상 리전, 조직의 규제 경계를 공식 문서에서 확인해야 한다.

PII 마스킹 기능을 사용하더라도 원본 문서, 추출 결과, 로그와 검토 화면에 대한 접근 제어는 별도로 설계해야 한다. CloudTrail 감사 로그, S3 데이터 이벤트, KMS 키 사용 기록을 활성화하고 보존 정책을 정하는 것이 좋다.

## 운영 관점

- 대표 문서 샘플로 필드별 정확도와 신뢰도 분포를 측정한 뒤 자동 승인 기준을 정한다.
- 낮은 신뢰도, 필수 필드 누락, 예상하지 못한 문서 유형은 사람 검토 대기열로 보낸다.
- 블루프린트를 버전 관리하고 변경 전후의 추출 결과를 회귀 테스트한다.
- 비동기 작업 상태, 실패율, 처리 시간, 페이지 수 및 비용을 모니터링한다.
- S3 입력·출력 경로에 수명 주기 정책을 적용해 민감 문서와 중간 결과를 필요한 기간만 보관한다.
- API 재시도 시 동일 문서가 중복 처리되지 않도록 작업 식별자와 멱등성 처리를 설계한다.
- 지원 리전 장애에 대비해 원본 보존, 재처리 절차 및 업무 연속성 계획을 마련한다.
- 페이지 단위 과금이므로 빈 페이지, 중복 문서 및 불필요한 첨부를 사전에 제거하는 방법을 검토한다.

## 시험 관점 정리

AWS 자격시험에서는 다음 연결 관계를 기억하면 좋다.

- **Amazon Textract**: 스캔 문서에서 텍스트, 필기, 표, 양식 데이터를 추출하는 관리형 서비스
- **Textract Insights**: 문서 분할·분류와 자연어 기반 필드 추출을 하나의 비동기 흐름으로 제공
- **Blueprint**: 추출할 필드와 의미를 JSON Schema 및 자연어 설명으로 정의
- **Confidence score**: 자동 처리와 사람 검토를 나누는 기준으로 활용
- **Grounding**: 추출 값이 나온 원본 페이지와 위치를 연결해 검증과 감사를 지원
- **Amazon S3**: 비동기 입력 문서와 결과 저장소
- **AWS KMS**: 프로젝트, 블루프린트 및 작업 데이터의 고객 관리형 암호화에 활용

여러 종류의 문서가 하나의 파일에 섞여 있고 결과의 근거와 신뢰도를 확인해야 하는 문제라면 Textract Insights가 적합한 후보가 될 수 있다. 단순 이미지 라벨 분류나 일반적인 자연어 생성 문제와는 목적이 다르다는 점도 구분해야 한다.

## 한 줄 정리

Amazon Textract Insights는 혼합 문서를 한 번에 분할·분류·구조화하고 각 결과에 신뢰도와 원본 위치를 제공해, 검증 가능한 지능형 문서 처리 파이프라인을 관리형 서비스로 구현하게 한다.
