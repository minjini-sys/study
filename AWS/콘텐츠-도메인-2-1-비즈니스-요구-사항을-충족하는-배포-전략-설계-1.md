# 콘텐츠 도메인 2-1. 비즈니스 요구 사항을 충족하는 배포 전략 설계(1)

관련 지식:

- 코드형 인프라(IaC)(예: AWS CloudFormation)
- 지속적 통합 및 지속적 전달(CI/CD)
- 변경 관리 프로세스
- 구성 관리 도구(예: AWS Systems Manager)

관련 기술:

- 새로운 서비스 및 기능에 대한 애플리케이션 또는 업그레이드 경로 결정
- 배포 전략을 개발하고 적절한 롤백 메커니즘을 구현하기 위한 서비스 선택
- 필요에 따라 관리형 서비스를 채택하여 인프라 프로비저닝 및 패치 오버헤드 감축
- 복잡한 개발 및 배포 작업을 AWS에 위임하여 고급 기술에 액세스

- 모범 사례 1: <mark>자동화</mark>를 통해 변경 사항 배포

배포와 패치를 자동화 한다.

패치: 기존 버전을 유지하면서 필요한 부분을 고친다.

- 모범 사례 2: 지금 서비스중인 서버를 패치하거나 업데이트 하지 말고 새로운 버전인 Immutable Infrastructure을 만든다.

이후 검증을 하고 교체를 한다.

또 배포가 실패했을 때 원래 버전으로 돌아가야 한다. (Rollback)

| 배포 방식 | 설명 |
| --- | --- |
| In-place | 기존 서버에서 v1-> v2로 업데이트 |
| Rolling | 서버들을 몇 대씩 순차적으로 v2로 교체 |
| Blue/Green (Immutable Infrastructure) | v1 환경과 별도로 v2 환경을 만들고 트래픽을 v2로 전환<br>Blue가 v1이고 Green가 v2이면 v2에서 문제가 생겼을 경우 Blue로 돌아가면 된다. |
| Canary | 일부 사용자/트래픽만 먼저 v2로 보내고 정상 확인 후 확대 |

- 인프라 프로비저닝 오버헤드 줄이는 방법

Iac인 CloudFormation 알기

Stack: 하나의 CloudFormation 템플릿으로 생성하고 관리하는 AWS 리소스들의 <mark>묶음</mark>

프로덕션 인프라를 업데이트하는 대신 새 스택을 배포할 수 있다.

- Template: 어떤 인프라를 만들 것인지 적어놓은 코드

CloudFormation이 Template을 실행하면 실제 AWS 리소스가 만들어진다.

- Stack: 이렇게 하나의 단위로 생성, 관리되는 실제 리소스 묶음을 말한다.

- 동일한 Template을 여러 환경에서 재사용할 수 있다.

AWS 공식 문서에서는 개발 환경에서는 저렴한 인스턴스 유형을 지정하고 운영환경에는 다른 인스턴스 유형을 지정하여 사용하는 예시를 둔다.

- <mark><b>Module:</b></mark> 반복적으로 사용하는 리소스의 구성을 CloudFormation Module로 만들어서 여러 Template에서 재사용 할 수 있다.

이라는 말이 나오면 CloudFormation Module을 골라야 한다.

- <mark><b>Nested Stack:</b></mark> 큰 CloudFormation을 작은 Stack들로 분리해서 재사용한다.

Stack 안에 다른 Stack을 사용하는 것이다.

- <mark><b>StackSets:</b></mark> 하나의 CloudFormation 구성을 여러 AWS 계정/리전에 한꺼번에 배포한다.

[공식 모범 사례]

multi-account, multi-region 배포에는 StackSets를 사용한다.

- <mark><b>Change Sets</b></mark>: Stack을 실제로 업데이트하기 전에 무엇이 어떻게 변경될 지 미리 보여주는 기능

[공식 모범 사례]

Change Set을 실행하기 전까지 CloudFormation은 Stack을 변경하지 않는다.

- <mark><b>Stack Policy</b></mark>: 중요한 Stack 리소스가 실수로 업데이트 되는 것을 막는 보호 정책

- <mark><b>Drift Detection</b></mark>: CloudFormation이 알고 있는 구성과 실제 리소스 구성이 달라졌는 지 탐지한다.

[공식 모범 사례]

CloudFormation이 만든 리소스는 CloudFormatiom을 통해 관리하는 것을 권장한다.

- <mark><b>Rollback Trigger</b></mark>: CloudFormation 업데이트 후 시스템에 문제가 생기면 자동으로 이전 상태로 돌리고 싶을 때 사용한다.
