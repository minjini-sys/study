### 1-3. ARP

IP주소를 아는데 MAC주소를 모를 때 MAC주소를 알기 위해 사용

1. ARP 요청

호스트 A가 브로드캐스트로 이 IP의 MAC주소가 무엇인지 ARP를 보낸다

2. ARP 응답

다른 호스트들은 자신의 IP가 아니기에 무시하고 B는 자신이 맞다고 자신의 MAC주소가 담긴 ARP를 보낸다

3. ARP 테이블

IP와 MAC주소 테이블을 호스트 A가 기록한다

## 2. IP 주소

네트워크 ID와 호스트 ID 범위를 유동적으로 IP주소에서 지정한다

### 2-1. 클래스 풀 주소 체계

| 클래스 | 주소 형태 | 범위 | 네트워크 수 | 호스트 수 |
| --- | --- | --- | --- | --- |
| A | 0네트워크 ID.호스트 ID. 호스트 ID. 호스트 ID | 0.0.0.0~127.255.255.255 | 2의 7승 | 2의 24승-2 |
| B | 10네트워크 ID. 네트워크 ID . 호스트 ID. 호스트 ID | 128.0.0.0~191.255.255.255 | 2의 14승 | 2의 16승-2 |
| C | 110네트워크 ID. 네트워크 ID . 네트워크 ID . 호스트 ID | 192.0.0.0~223.255.255.255 | 2의 21승 | 2의 8승 -2 |

호스트 주소가 모두 0이거나 모두 1인 것은 각각 네트워크 자체를 나타내는 네트워크 주소와 브로드캐스트 주소이니 호스트의 주소로 사용할 수 없다

클래스는 낭비가 되는 IP 주소가 많을 수 있다 예를 들어 300개의 호스트 네트워크 영역을 만들려고 할 때 어쩔 수 없이 클래스 B를 만들어야 한다. 300개를 쓰려고 대략적으로 6만개 이상의 호스트 IP 주소 영역을 할당하는 것이기에 많은 낭비가 발생한다

### 2-2. 클래스리스 주소 체계

이를 해결하는 것이 클래스리스 주소 체계이다.

이는 네트워크 주소를 1, 호스트 주소를 0으로 표현한다.

| 클래스 | 서브넷 마스크 |
| --- | --- |
| A | 11111111.00000000.00000000.00000000 |
| B | 11111111.11111111.00000000.00000000 |
| C | 11111111.11111111. 11111111.00000000 |

IP 주소와 서브넷 마스크를 AND 연산(둘다 1이면 1)하면 네트워크 주소가 나온다.
