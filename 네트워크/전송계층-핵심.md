# 전송계층 핵심

네트워크 계층에서 IP 주소를 이용해 목적지 호스트까지 패킷을 보냈다면, 전송계층은 그 호스트 안에서 어떤 애플리케이션으로 데이터를 전달할지 결정한다.

즉, 네트워크 계층이 "어느 컴퓨터로 보낼까?"를 담당한다면 전송계층은 "그 컴퓨터 안의 어떤 프로그램으로 보낼까?"를 담당한다.

## 1. 전송계층의 역할

전송계층은 송신지와 수신지의 프로세스 사이에서 통신을 제공한다.

프로세스는 실행 중인 프로그램을 말한다. 예를 들어 웹 브라우저, 카카오톡, 게임 클라이언트 같은 것들이 프로세스이다.

전송계층의 대표적인 역할은 다음과 같다.

- 포트 번호를 통해 애플리케이션을 구분한다.
- 데이터를 세그먼트 단위로 나눈다.
- TCP를 사용하면 신뢰성 있는 전송을 제공한다.
- UDP를 사용하면 빠르고 단순한 전송을 제공한다.

## 2. 포트 번호

IP 주소가 호스트를 찾기 위한 주소라면, 포트 번호는 호스트 안의 애플리케이션을 찾기 위한 번호이다.

예를 들어 내 컴퓨터에서 웹 브라우저도 실행 중이고, 메신저도 실행 중이고, 게임도 실행 중일 수 있다. 이때 도착한 데이터가 어떤 프로그램으로 가야 하는지 구분하기 위해 포트 번호를 사용한다.

| 구분 | 범위 | 설명 |
| --- | --- | --- |
| 잘 알려진 포트 | 0~1023 | HTTP, HTTPS, DNS처럼 대표 서비스가 사용하는 포트 |
| 등록된 포트 | 1024~49151 | 특정 애플리케이션이 등록해서 사용하는 포트 |
| 동적 포트 | 49152~65535 | 클라이언트가 임시로 사용하는 포트 |

대표적인 포트 번호는 다음과 같다.

| 포트 번호 | 프로토콜 | 설명 |
| --- | --- | --- |
| 20, 21 | FTP | 파일 전송 |
| 22 | SSH | 원격 접속 |
| 53 | DNS | 도메인 이름을 IP 주소로 변환 |
| 80 | HTTP | 웹 통신 |
| 443 | HTTPS | 암호화된 웹 통신 |

## 3. TCP와 UDP

전송계층의 대표 프로토콜은 TCP와 UDP이다.

TCP는 신뢰성 있는 연결형 프로토콜이고, UDP는 빠른 비연결형 프로토콜이다.

| 구분 | TCP | UDP |
| --- | --- | --- |
| 연결 방식 | 연결형 | 비연결형 |
| 신뢰성 | 높다 | 낮다 |
| 속도 | 상대적으로 느리다 | 상대적으로 빠르다 |
| 순서 보장 | 보장한다 | 보장하지 않는다 |
| 오류 제어 | 한다 | 거의 하지 않는다 |
| 사용 예시 | 웹, 이메일, 파일 전송 | 실시간 영상, 음성, 게임, DNS |

## 4. TCP

TCP는 데이터를 정확하고 순서대로 전달하기 위해 여러 기능을 제공한다.

TCP는 데이터를 보내기 전에 먼저 연결을 맺는다. 이 연결 과정이 3-way handshake이다.

### 4-1. 3-way handshake

3-way handshake는 TCP 연결을 시작할 때 사용하는 과정이다.

1. 클라이언트가 서버에게 SYN을 보낸다.
2. 서버가 클라이언트에게 SYN + ACK를 보낸다.
3. 클라이언트가 서버에게 ACK를 보낸다.

이 과정을 통해 서로 통신할 준비가 되었는지 확인한다.

쉽게 말하면 다음과 같다.

1. 클라이언트: 연결해도 돼?
2. 서버: 응, 나도 연결할게.
3. 클라이언트: 좋아, 이제 보내자.

### 4-2. 4-way handshake

TCP 연결을 종료할 때는 4-way handshake를 사용한다.

1. 한쪽이 FIN을 보내 연결 종료를 요청한다.
2. 상대방이 ACK로 확인한다.
3. 상대방도 FIN을 보내 종료를 요청한다.
4. 처음 FIN을 보냈던 쪽이 ACK로 확인한다.

연결을 시작할 때보다 종료할 때 과정이 더 긴 이유는, 한쪽은 보낼 데이터가 끝났어도 다른 쪽은 아직 보낼 데이터가 남아 있을 수 있기 때문이다.

## 5. TCP의 신뢰성 보장 방법

TCP는 데이터를 그냥 보내고 끝내지 않는다. 잘 도착했는지 확인하고, 문제가 생기면 다시 보낸다.

### 5-1. 순서 번호와 확인 응답

TCP는 데이터에 순서 번호를 붙인다.

수신자는 데이터를 받으면 ACK를 보내 잘 받았다고 알려준다.

만약 ACK가 오지 않으면 송신자는 데이터가 손실되었다고 판단하고 다시 보낸다.

### 5-2. 재전송

네트워크에서는 패킷이 중간에 사라질 수 있다.

TCP는 일정 시간 안에 ACK가 오지 않으면 데이터를 다시 전송한다.

이 덕분에 TCP는 신뢰성이 높다.

### 5-3. 흐름 제어

흐름 제어는 수신자가 처리할 수 있는 만큼만 데이터를 보내도록 조절하는 것이다.

송신자가 너무 빠르게 데이터를 보내면 수신자의 버퍼가 넘칠 수 있다. 그래서 TCP는 수신자가 받을 수 있는 양을 확인하면서 데이터를 보낸다.

여기서 사용하는 대표적인 방식이 슬라이딩 윈도우이다.

### 5-4. 혼잡 제어

혼잡 제어는 네트워크가 너무 붐비지 않도록 송신 속도를 조절하는 것이다.

흐름 제어가 수신자의 상태를 고려하는 것이라면, 혼잡 제어는 네트워크 전체의 상태를 고려하는 것이다.

<mark>흐름 제어는 수신자 보호, 혼잡 제어는 네트워크 보호라고 생각하면 된다.</mark>

## 6. UDP

UDP는 TCP보다 단순하다.

연결을 맺는 과정도 없고, 데이터가 잘 도착했는지 확인하는 과정도 거의 없다.

그래서 신뢰성은 낮지만 속도가 빠르다.

UDP는 실시간성이 중요한 서비스에서 많이 사용된다.

- 실시간 스트리밍
- 인터넷 전화
- 온라인 게임
- DNS

실시간 영상 통화에서 데이터 하나가 조금 손실되었다고 다시 보내면 오히려 대화가 끊길 수 있다. 이런 경우에는 정확성보다 빠른 전달이 더 중요하다.

## 7. 캡슐화와 역캡슐화

전송계층에서 만든 데이터 단위를 세그먼트라고 한다.

다만 UDP에서는 데이터그램이라고 부르기도 한다.

송신 과정에서는 애플리케이션 데이터에 TCP 또는 UDP 헤더가 붙는다.

수신 과정에서는 반대로 헤더를 하나씩 제거하며 원래 데이터가 애플리케이션으로 전달된다.

| 계층 | 데이터 단위 |
| --- | --- |
| 응용계층 | 메시지 |
| 전송계층 | 세그먼트 또는 데이터그램 |
| 네트워크 계층 | 패킷 |
| 데이터링크 계층 | 프레임 |

## 8. 정리

전송계층은 호스트와 호스트 사이의 통신을 프로세스와 프로세스 사이의 통신으로 확장해준다.

포트 번호를 이용해 애플리케이션을 구분하고, TCP 또는 UDP를 이용해 상황에 맞는 전송 방식을 선택한다.

TCP는 정확한 전달이 중요할 때 사용하고, UDP는 빠른 전달이 중요할 때 사용한다.

<mark>전송계층의 핵심은 포트 번호, TCP, UDP이다.</mark>
