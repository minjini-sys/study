# A급: 반드시 알아야 하는 내용

## 1. 운영체제의 정의와 역할

운영체제는 **사용자 및 응용 프로그램과 컴퓨터 하드웨어 사이에서 중개자 역할을 하는 소프트웨어**이다.

운영체제의 핵심 역할은 다음 두 가지 관점으로 설명할 수 있다.

- **자원 할당자(Resource Allocator):** CPU, 메모리, 파일, 저장장치, 입출력 장치를 프로세스에 배분한다.
- **제어 프로그램(Control Program):** 프로그램의 실행을 관리하고 오류나 부적절한 사용을 막는다.

운영체제의 목표는 다음과 같다.

- 사용자 프로그램을 실행한다.
- 사용자가 컴퓨터를 편리하게 사용할 수 있게 한다.
- 컴퓨터 하드웨어를 효율적으로 사용한다.

컴퓨터 시스템의 구성:

```text
사용자
  ↓
응용 프로그램
  ↓
운영체제
  ↓
하드웨어(CPU, 메모리, 입출력 장치)
```

**커널(Kernel)**은 운영체제의 핵심 부분으로, 시스템이 동작하는 동안 존재하며 핵심 관리 기능을 수행한다.

## 2. Device Controller와 Device Driver

| 용어 | 종류 | 역할 |
|---|---|---|
| Device Controller | 하드웨어 | CPU와 실제 장치 사이의 통신을 중개한다. |
| Device Driver | 소프트웨어 | 운영체제가 특정 장치 컨트롤러를 사용할 수 있게 한다. |
| Local Buffer | 임시 저장 공간 | 장치와 메모리 사이에서 이동하는 데이터를 잠시 저장한다. |

기본적인 관계:

```text
운영체제
  ↓
Device Driver
  ↓
Device Controller
  ↓
실제 입출력 장치
```

장치 작업이 끝나면 Device Controller가 CPU에 인터럽트를 발생시켜 완료 사실을 알린다.

## 3. 인터럽트

### 3.1 인터럽트란?

인터럽트는 CPU의 처리가 필요한 사건이 발생했다는 것을 알리는 신호이다.

예:

- 키보드 입력
- 디스크 읽기 완료
- 네트워크 데이터 도착
- 타이머 만료

### 3.2 인터럽트 처리 과정

```text
① CPU가 사용자 프로그램을 실행한다.
② 장치 컨트롤러가 인터럽트를 발생시킨다.
③ CPU가 현재 실행 상태를 저장한다.
④ CPU가 인터럽트 번호를 확인한다.
⑤ 인터럽트 벡터에서 처리 코드의 주소를 찾는다.
⑥ 인터럽트 서비스 루틴(ISR)을 실행한다.
⑦ 저장했던 CPU 상태를 복원한다.
⑧ 원래 프로그램의 실행을 재개한다.
```

### 3.3 핵심 용어

- **Interrupt Vector:** 인터럽트 종류별 처리 코드의 주소를 저장한 표.
- **Interrupt Service Routine(ISR):** 인터럽트 발생 시 실제로 실행되는 처리 코드.
- **Interrupt Handler:** ISR과 같은 의미로 사용되는 표현.
- **Program Counter(PC):** 다음에 실행할 명령어의 주소를 저장하는 레지스터.
- **CPU 상태 저장:** 인터럽트 처리 후 원래 프로그램을 정확한 위치에서 재개하기 위해 필요하다.

인터럽트 벡터에는 처리 코드 자체가 아니라 **처리 코드가 메모리 어디에 있는지를 나타내는 주소**가 들어 있다.

### 3.4 인터럽트와 예외

| 구분 | 발생 원인 | 예 |
|---|---|---|
| Hardware Interrupt | CPU 외부 장치에서 발생 | 키보드 입력, 디스크 작업 완료 |
| Exception | 현재 CPU가 실행한 명령어 때문에 발생 | 0으로 나누기, 잘못된 명령어, 페이지 폴트 |
| Trap | 의도적으로 운영체제에 진입하거나 특정 종류의 예외를 나타냄 | 시스템 호출, 중단점 |

하드웨어 인터럽트와 예외 모두 사건별 처리 코드가 필요하며, 인터럽트 벡터의 대응 항목을 통해 처리될 수 있다.

## 4. 다중 프로그래밍과 다중 작업

| 개념 | 핵심 목적 | 동작 방식 |
|---|---|---|
| Multiprogramming | CPU 이용률 향상 | 한 작업이 입출력을 기다리면 다른 작업을 실행한다. |
| Multitasking / Timesharing | 빠른 사용자 응답 | 여러 작업 사이를 매우 자주 전환한다. |

예를 들어 프로세스 A가 디스크 읽기를 기다리는 동안 B를 실행하는 것은 다중 프로그래밍이다. A, B, C를 짧은 시간씩 번갈아 실행하여 모두 반응하는 것처럼 보이게 하는 것은 다중 작업 또는 시분할이다.

관련 용어:

- **Process:** 실행 중인 프로그램.
- **CPU Scheduling:** 실행 가능한 프로세스 중 다음 실행 대상을 선택하는 일.
- **Swapping:** 프로세스를 메모리와 저장장치 사이로 이동시키는 것.
- **Virtual Memory:** 프로세스 전체가 RAM에 올라와 있지 않아도 실행할 수 있게 하는 기술.
- **Concurrency:** 여러 작업의 실행이 같은 기간에 걸쳐 진행되는 것. CPU 하나에서 번갈아 실행하는 경우도 포함한다.

## 5. 사용자 모드와 커널 모드

이중 모드 동작은 운영체제와 다른 프로그램을 보호하기 위해 사용한다.

| 구분 | 사용자 모드 | 커널 모드 |
|---|---|---|
| 주로 실행하는 코드 | 일반 응용 프로그램 | 운영체제 커널 |
| 권한 | 제한됨 | 특권 명령 실행 가능 |
| 슬라이드의 Mode Bit | 1 | 0 |

### 특권 명령

특권 명령은 커널 모드에서만 실행할 수 있는 명령이다.

예:

- 입출력 장치 제어
- 타이머 설정
- 인터럽트 관리
- 실행 모드 변경

사용자 프로그램이 특권 명령을 직접 실행하려 하면 하드웨어가 실행을 막고 운영체제로 트랩한다.

### 시스템 호출 과정

```text
사용자 프로그램 실행
      ↓ 시스템 호출
사용자 모드 → 커널 모드
      ↓
커널이 요청을 검사하고 처리
      ↓
커널 모드 → 사용자 모드
      ↓
사용자 프로그램 실행 재개
```

시스템 호출은 사용자 프로그램이 커널 권한을 얻는 것이 아니다. 사용자 프로그램이 **커널에 작업을 대신 수행해 달라고 요청하는 방법**이다.

## 6. 타이머

타이머는 프로세스의 CPU 독점을 막고 운영체제가 CPU 제어권을 되찾기 위해 사용한다.

```text
운영체제가 타이머 설정
       ↓
사용자 프로세스 실행
       ↓
클록 신호에 따라 카운터 감소
       ↓
카운터가 0이 됨
       ↓
타이머 인터럽트 발생
       ↓
운영체제가 제어권 회수
```

타이머가 없으면 프로그램이 무한 루프에 빠졌을 때 CPU를 계속 차지할 수 있다.

타이머 설정은 **특권 명령**이다. 일반 프로그램이 타이머를 끄거나 변경할 수 있으면 운영체제가 CPU를 회수하지 못할 수 있기 때문이다.

타이머 인터럽트가 발생했다고 프로그램이 항상 종료되는 것은 아니다. 운영체제가 다음 프로세스로 전환하거나, 시간을 더 주거나, 필요한 경우 프로그램을 종료할 수 있다.

## 7. 프로그램과 프로세스

| 프로그램 | 프로세스 |
|---|---|
| 저장장치에 보관된 코드 | 실행 중인 프로그램 |
| 수동적 존재 | 능동적 존재 |
| 그 자체로 CPU를 사용하지 않음 | CPU, 메모리, 파일 등의 자원을 사용 |

같은 프로그램을 두 번 실행하면 프로그램 파일은 하나여도 프로세스는 두 개가 될 수 있다.

프로세스에는 다음과 같은 자원이 필요하다.

- CPU 시간
- 메모리
- 입출력 장치
- 파일
- 초기화 데이터

프로세스가 종료되면 운영체제는 재사용 가능한 자원을 회수한다.

## 8. 프로세스, 스레드와 프로그램 카운터

- **단일 스레드 프로세스:** 프로그램 카운터가 하나이다.
- **다중 스레드 프로세스:** 각 스레드마다 프로그램 카운터가 하나씩 필요하다.

스레드마다 다음에 실행할 명령어의 위치가 다르기 때문이다.

운영체제의 프로세스 관리 활동:

- 사용자 및 시스템 프로세스 생성·삭제
- 프로세스와 스레드의 CPU 스케줄링
- 프로세스 일시 중지·재개
- 프로세스 동기화 기능 제공
- 프로세스 간 통신 기능 제공

## 9. 저장장치 계층

```text
레지스터
   ↓
캐시
   ↓
주기억장치(RAM)
   ↓
비휘발성 메모리·SSD
   ↓
HDD
   ↓
광디스크·자기 테이프
```

위쪽으로 갈수록 대체로 속도가 빠르고 용량이 작으며 용량당 가격이 비싸다. 아래쪽으로 갈수록 속도가 느리고 용량이 크며 용량당 가격이 저렴하다.

- **RAM:** CPU가 직접 접근하는 주요 작업 공간이며 일반적으로 휘발성이다.
- **SSD·HDD:** 전원이 꺼져도 데이터가 유지되는 보조기억장치이다.
- **1 Byte = 8 bits**

## 10. 캐싱과 캐시 일관성

캐싱은 느린 저장장치의 데이터를 더 빠른 저장 공간에 임시로 복사하는 것이다.

```text
디스크 → RAM → 캐시 → 레지스터 → CPU에서 처리
느림                              빠름
```

- **Cache Hit:** 필요한 데이터가 캐시에 있어서 바로 사용하는 경우.
- **Cache Miss:** 캐시에 데이터가 없어 원래 저장장치에서 가져오는 경우.
- **Replacement Policy:** 캐시가 가득 찼을 때 어떤 데이터를 제거할지 정하는 정책.
- **Cache Coherency:** 여러 CPU 캐시에 같은 데이터의 복사본이 있을 때 모두 최신 값을 보도록 유지하는 성질.

## 11. 메모리 관리

프로그램을 실행하려면 필요한 명령어와 데이터의 전부 또는 일부가 메모리에 있어야 한다.

운영체제의 메모리 관리 활동:

- 현재 메모리의 어느 부분이 사용 중인지 기록한다.
- 각 공간을 어떤 프로세스가 사용하는지 기록한다.
- 필요한 메모리 공간을 할당한다.
- 사용이 끝난 메모리 공간을 할당 해제한다.
- 어떤 프로세스와 데이터를 언제 메모리에 넣고 뺄지 결정한다.

핵심 문장:

> 메모리 관리는 무엇을 언제 메모리에 둘지 결정한다.

## 12. 파일 시스템과 대용량 저장장치 관리

운영체제는 복잡한 물리적 저장장치를 **파일과 디렉터리라는 논리적인 형태로 추상화**한다.

파일 시스템 관리:

- 파일 생성·삭제
- 디렉터리 생성·삭제
- 파일 읽기·쓰기
- 접근 권한 관리
- 파일을 실제 저장 공간에 대응시키기
- 파일 백업

대용량 저장장치 관리:

- Mounting과 Unmounting
- 남은 공간 관리
- 저장 공간 할당
- 디스크 요청 순서 결정
- 파티션 분할
- 저장 데이터 보호

## 13. Buffering, Caching, Spooling

| 개념 | 의미 |
|---|---|
| Buffering | 데이터 전송 속도 차이를 처리하기 위해 데이터를 잠시 저장한다. |
| Caching | 재사용할 가능성이 있는 데이터를 빠른 공간에 복사한다. |
| Spooling | 느린 장치가 처리할 작업을 대기 공간에 모아 둔다. |

프린터 스풀링:

```text
여러 프로그램의 인쇄 요청
          ↓
인쇄 대기열에 저장
          ↓
프로그램은 다른 작업을 계속 수행
          ↓
프린터가 요청을 순서대로 처리
```

## 14. 단일 프로세서, 다중 프로세서와 멀티코어

- **CPU/Core:** 명령어를 실행하는 계산 단위.
- **Processor:** 하나 이상의 CPU 코어를 포함하는 물리적인 칩.
- **Multicore:** 하나의 프로세서 칩 안에 여러 코어가 있는 구성.
- **Multiprocessor:** 여러 프로세서를 사용하는 시스템.

다중 프로세서 시스템의 장점:

- 처리량 증가
- 규모의 경제
- 신뢰성 향상 가능

다중 처리 방식:

- **Asymmetric Multiprocessing:** 각 프로세서에 특정 역할이 지정된다.
- **Symmetric Multiprocessing(SMP):** 각 프로세서가 여러 종류의 작업을 수행할 수 있다.

CPU가 N개라면 최대 N개의 프로세스를 물리적으로 동시에 실행할 수 있다.

## 15. NUMA

NUMA는 **Non-Uniform Memory Access**, 즉 비균일 메모리 접근 구조이다.

- 모든 CPU가 하나의 물리 주소 공간을 공유한다.
- CPU마다 가까운 메모리와 먼 메모리가 있다.
- 어느 메모리에 접근하느냐에 따라 접근 시간이 달라진다.

```text
메모리를 공유하는가? → 그렇다.
모든 메모리의 접근 시간이 같은가? → 아니다.
```

## 16. Protection과 Security

| 개념 | 의미 | 예 |
|---|---|---|
| Protection | 사용자와 프로세스의 자원 접근을 통제한다. | 다른 사용자의 파일 읽기 금지 |
| Security | 내부·외부 공격으로부터 시스템을 방어한다. | 바이러스, 해킹, 서비스 거부 공격 방어 |

- **User ID:** 개별 사용자를 식별한다.
- **Group ID:** 여러 사용자를 그룹으로 묶어 권한을 관리한다.
- **Privilege Escalation:** 필요한 경우 더 높은 유효 권한으로 변경하는 것.

암기 문장:

> Protection은 접근 통제이고, Security는 공격 방어이다.

## 17. 가상화와 에뮬레이션

가상화는 하나의 실제 컴퓨터에서 여러 운영체제를 각각 독립적인 컴퓨터처럼 실행하게 하는 기술이다.

```text
실제 하드웨어
     ↓
가상 머신 관리자(VMM)
 ┌────┼────┐
Guest OS  Guest OS  Guest OS
```

- **Host:** 가상화 환경의 기반이 되는 시스템.
- **Guest OS:** 가상 머신 안에서 실행되는 운영체제.
- **VMM:** 가상 머신을 생성하고 관리하는 가상 머신 관리자. 하이퍼바이저라고도 한다.

| 가상화 | 에뮬레이션 |
|---|---|
| 같은 계열 CPU의 기능을 직접 활용한다. | 다른 CPU 구조를 소프트웨어로 흉내 낸다. |
| 일반적으로 더 효율적이다. | 명령어 변환 때문에 일반적으로 느리다. |

가상화의 활용:

- 한 컴퓨터에서 여러 운영체제 실행
- 여러 운영체제용 프로그램 개발 및 테스트
- 가상 머신 사이의 오류 격리
- 데이터센터의 서버 자원 활용

## 18. 커널 자료구조

- **연결 리스트:** 각 원소가 다음 원소의 위치를 가리킨다.
- **스택:** LIFO, 나중에 넣은 것을 먼저 꺼낸다.
- **큐:** FIFO, 먼저 넣은 것을 먼저 꺼낸다.
- **이진 탐색 트리:** 값의 크기를 기준으로 데이터를 나누어 저장한다.
- **균형 이진 탐색 트리:** 일반적으로 `O(log n)` 시간에 검색할 수 있다.

스택은 함수의 매개변수, 지역 변수, 복귀 주소 등에 사용될 수 있다. 큐는 프린터 작업이나 프로세스 대기열에 사용될 수 있다.

## 19. 컴퓨팅 환경

### 클라이언트-서버

- 클라이언트가 서비스를 요청한다.
- 서버가 요청을 처리하고 결과를 제공한다.
- 클라이언트와 서버의 역할이 구분된다.

### P2P

- 고정된 클라이언트와 서버의 구분이 없다.
- 각 노드가 클라이언트, 서버 또는 두 역할을 모두 수행할 수 있다.

### 클라우드 컴퓨팅

네트워크를 통해 컴퓨팅 자원과 서비스를 제공한다.

| 서비스 모델 | 제공 대상 | 쉽게 말하면 |
|---|---|---|
| SaaS | 완성된 응용 프로그램 | 프로그램을 빌린다. |
| PaaS | 프로그램 개발·실행 환경 | 개발 환경을 빌린다. |
| IaaS | 서버, 저장장치, 네트워크 등의 인프라 | 컴퓨터 자원을 빌린다. |

클라우드 유형:

- **Public Cloud:** 비용을 내는 일반 사용자가 인터넷을 통해 사용한다.
- **Private Cloud:** 한 조직이 자체적으로 사용한다.
- **Hybrid Cloud:** 공용 클라우드와 사설 클라우드를 결합한다.

### 실시간 임베디드 시스템

특정 장치 안에서 정해진 기능을 수행하며, 지정된 시간 제한 안에 처리를 완료해야 한다.

> 실시간 시스템에서는 결과가 정확하더라도 정해진 시간을 넘기면 올바른 동작이 아니다.

# 시험 직전 암기 문장

1. 운영체제는 사용자 및 응용 프로그램과 하드웨어 사이의 중개자이다.
2. 운영체제는 자원 할당자이자 제어 프로그램이다.
3. 커널은 운영체제의 핵심 부분이다.
4. 장치 컨트롤러는 하드웨어이고 장치 드라이버는 소프트웨어이다.
5. 인터럽트 벡터는 인터럽트별 처리 코드의 주소를 저장한 표이다.
6. ISR은 인터럽트 발생 시 실제로 실행되는 처리 코드이다.
7. 인터럽트 처리 전에 CPU 상태를 저장하는 이유는 원래 프로그램의 실행을 재개하기 위해서이다.
8. 다중 프로그래밍의 주목적은 CPU 이용률 향상이다.
9. 다중 작업의 주목적은 빠른 사용자 응답이다.
10. 시스템 호출은 사용자 프로그램이 커널에 서비스를 요청하는 방법이다.
11. 특권 명령은 커널 모드에서만 실행할 수 있다.
12. 타이머는 운영체제가 CPU 제어권을 되찾을 수 있게 한다.
13. 프로그램은 수동적 존재이고 프로세스는 능동적 존재이다.
14. 단일 스레드 프로세스는 프로그램 카운터가 하나이고, 다중 스레드 프로세스는 스레드마다 하나씩 가진다.
15. 메모리 관리는 무엇을 언제 메모리에 둘지 결정한다.
16. 파일 시스템은 물리적 저장장치를 파일과 디렉터리라는 논리적 형태로 추상화한다.
17. 캐시 일관성은 여러 CPU의 캐시가 데이터의 최신 값을 보도록 유지하는 성질이다.
18. NUMA에서는 주소 공간은 공유하지만 메모리 접근 시간은 균일하지 않다.
19. Protection은 접근 통제이고 Security는 공격 방어이다.
20. 실시간 시스템은 정해진 시간 제한을 지켜야 올바르게 동작한 것이다.

# 5분 최종 점검

다음 흐름을 말로 설명할 수 있는지 확인한다.

```text
입출력 장치 작업 완료
→ Device Controller가 인터럽트 발생
→ CPU가 현재 상태 저장
→ Interrupt Vector에서 ISR 주소 확인
→ ISR 실행
→ 상태 복원
→ 원래 프로그램 재개
```

```text
사용자 프로그램
→ System Call
→ 사용자 모드에서 커널 모드로 전환
→ 커널이 요청 처리
→ 사용자 모드로 복귀
```

```text
프로세스에 CPU 할당
→ 타이머 설정
→ 시간 만료
→ 타이머 인터럽트
→ 운영체제가 CPU 제어권 회수
```

다음 차이를 한 문장씩 설명할 수 있는지 확인한다.

- Controller와 Driver
- Program과 Process
- Multiprogramming과 Multitasking
- User Mode와 Kernel Mode
- Interrupt와 Exception
- Buffering과 Caching과 Spooling
- Protection과 Security
- Virtualization과 Emulation
- Client-Server와 P2P
- SaaS와 PaaS와 IaaS
